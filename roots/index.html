Vicrix is an API-first creator directory and profile platform designed to bring creator information, channel data, social links, and structured public profiles into one organized ecosystem. Built with a developer-first approach, Vicrix aims to make creator data easier to access, display, and integrate into other applications.

01 · Project overview

What exactly is Vicrix?

Vicrix is being designed as a centralized system for storing, presenting, and serving creator profile information through a website and developer-friendly APIs.

01

Creator Directory

An organized directory where individual creators can have dedicated profile pages containing their identity, biography, social links, and available public platform information.

02

Unified Profiles

A consistent profile structure that can bring together information from supported platforms instead of displaying every platform in a completely different format.

03

API-First Architecture

A backend API designed to return structured creator data that other websites, dashboards, and applications can consume when authorized and technically supported.

Project status: This website explains the Vicrix vision and proposed architecture. Features described as planned are not necessarily implemented or publicly available. Actual functionality depends on the code deployed in the official repository.

02 · Purpose

Why is Vicrix being built?

Creator information is spread across multiple platforms. Vicrix aims to provide a more structured way to organize that information and make it useful for both visitors and developers.

Reduce fragmented information

Keep a creator's biography, channel identity, and supported social links together in one profile.

Make integration simpler

Provide a consistent API response so consuming applications do not need to build a separate profile data structure for every creator.

Support future growth

Build a foundation that can later support search, creator discovery, more integrations, profile management, and additional developer tools.

Improve profile presentation

Give each creator a dedicated URL with organized content, readable information, and search-engine-friendly metadata.

Keep data structured

Store creator records in a database instead of relying entirely on hardcoded profile information across pages.

Enable reusable infrastructure

Create a foundation that other projects may integrate with when the necessary API endpoints, access rules, and documentation are available.

05 · Technology stack

How is Vicrix being built?

The proposed stack separates the presentation layer, application logic, database, and external platform integrations.

Next.js

Application framework for routing, server-rendered pages, metadata, and API route handlers.

React

Component-based user interfaces and reusable profile layouts within the Next.js application.

Tailwind CSS

Utility-first styling for consistent spacing, responsive layouts, and maintainable UI development.

Supabase

PostgreSQL database infrastructure for creator records, profile slugs, platform identifiers, and application data.

YouTube Data API

External API integration for supported channel and video information, subject to quota and API policies.

REST API + JSON

HTTP endpoints that validate requests and return structured responses for frontend pages and authorized consumers.

Configuration: API keys and privileged database credentials belong in server-side environment variables. Secret keys must never be embedded in public browser JavaScript or committed to a public repository.

06 · System architecture

How does the system work?

The intended request flow moves from the visitor to the application, through server-side data services, and back to a rendered profile or JSON response.

01. Visitor or External Application Opens a creator profile or requests API data.
↓
02. Next.js Application Routes the request and renders the page or handles the API call.
↓
03. Server-Side Data Layer Validates the request, retrieves records, and applies caching rules.
↓
04. Supabase + Supported External APIs Supabase stores records; approved APIs provide available platform data.
↓
05. Normalized Response The application returns structured JSON or displays a creator profile.

07 · Data design

How creator data is organized

A proposed database structure separates a creator's identity from the platform identifiers used to retrieve external data.

Field Purpose Example
id Unique database record identifier UUID
slug Creator's URL identifier example-creator
name Display name Example Creator
custom_bio Creator biography Public profile description
yt_channel_id YouTube channel identifier Channel ID
ig_handle Instagram account handle examplecreator
fb_page_id Facebook Page identifier Page ID
created_at Record creation timestamp Timestamp
updated_at Last record update Timestamp

This is a proposed initial schema. Production implementation may need additional tables for platform connections, credentials, permissions, API usage, audit logs, and creator verification. Private credentials should not be stored as ordinary public profile fields.

09 · Security & reliability

Built with responsible data handling in mind

A reliable creator platform needs more than profile pages. It also needs secure credentials, predictable API behavior, and appropriate data access controls.

Secrets and access control

✓

Keep service-role keys and API secrets on the server.

✓

Validate input and restrict access to private operations.

✓

Use appropriate database permissions and access policies.

Performance and reliability

✓

Cache external data where permitted and useful.

✓

Handle missing records, timeouts, and quota errors.

✓

Plan rate limiting, monitoring, and abuse prevention.

Questions about Vicrix

What is Vicrix?

Which technologies are used?
